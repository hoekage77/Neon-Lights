Architecture Decisions Log

Decision: Quality Presets Over Dynamic Scaling

Date: May 15, 2026

Decision: Implemented three discrete quality levels (LOW/MEDIUM/HIGH) instead of continuous dynamic scaling.

Rationale: Easier to test, debug, and reason about. Players can manually override. Discrete steps make it clear what's enabled/disabled.

Trade-off: Less granular than per-feature toggles, but simpler implementation and maintenance.

Decision: Procedural Geometry Phase 1

Date: May 15, 2026

Decision: All Phase 1 geometry is procedurally generated (boxes, cylinders) instead of loading GLB models.

Rationale: Eliminates asset pipeline dependency. No external files to load = no 404 errors. Instant iteration. Proves the architecture works before investing in art.

Trade-off: Visual fidelity is low (everything is a box). Will replace with actual models in Phase 2.

Decision: HTML/CSS UI Over Canvas UI

Date: May 15, 2026

Decision: All UI (menus, HUD, dialogs) is HTML/CSS layered over the WebGL canvas.

Rationale: Easier to style, accessible, SEO-friendly, faster to iterate. No need to rebuild UI on canvas resize.

Trade-off: Slight overhead of DOM + WebGL. Could consider Canvas UI for in-game HUD later if performance demands it.

Decision: ES6 Modules with Vite

Date: May 15, 2026

Decision: Using native ES6 modules with Vite bundler (no TypeScript for Phase 1).

Rationale: Fast dev server with HMR. No build-step complexity. Code splitting works out of the box. Can migrate to TypeScript later.

Trade-off: No compile-time type checking. IDE autocomplete less precise than TS. Planning TS migration for Phase 2.
