1 Project Vision & Core Concept

1.1 The Big Idea

Neon City Arcade is a browser-based 3D platform where players explore a stylized, neon-lit city street and enter various venues to play arcade-style games. Inspired by mobile life simulation games (Miami Nights style), the experience blends open-world exploration with curated game content.

1.2 Core Pillars

  • Exploration: Players walk around a living 3D world, discovering venues organically
  • Immersion: The city feels alive with NPCs, dynamic lighting, and atmospheric effects
  • Accessibility: Runs in any modern browser, no installation required
  • Performance: 60fps target on mid-range devices, optimized for WebGL
  • Extensibility: Designed to easily add new venues and games over time

1.3 Target Audience

  • Casual gamers who enjoy browser-based experiences
  • Fans of arcade and retro gaming aesthetics
  • Players who enjoy light exploration and social elements
  • Age rating: E for Everyone (cartoonish, no violence)

1.4 Platform Requirements

Requirement Specification
Minimum Browser Chrome 90+, Firefox 88+, Safari 14+, Edge 90+
WebGL Version WebGL 2.0 (fallback to WebGL 1.0 with reduced effects)
Target FPS 60fps on desktop, 30fps minimum on mobile
Screen Support Responsive: 1920x1080 down to 375x667 (mobile)
Input Methods Keyboard + Mouse (primary), Touch (secondary), Gamepad (future)

2.3 Module System

All game logic is organized into ES6 modules. Each major system is a self-contained module with clear input/output interfaces. The GameController acts as the central orchestrator.

Key Principle: Each game module (Sky Ace, etc.) is completely self-contained. It receives a Three.js scene, camera, and renderer from the platform, but manages its own game loop, input, and state. When the player exits, the module cleans up all its resources.

4.3 Memory Management

CRITICAL: All classes that create Three.js objects (meshes, materials, textures, geometries) MUST implement a dispose() method. Call this when transitioning between states (e.g., leaving a game venue). Failure to dispose resources will cause memory leaks and crash the browser.

4.4 Performance Rules

  1. Geometry Reuse: Use InstancedMesh for repeated objects (street lamps, trees, etc.)
  2. Texture Sizes: Max 2048x2048 for hero assets, 512x512 for props, 256x256 for UI
  3. Draw Calls: Target under 200 draw calls for the street scene
  4. Shadows: Use baked lighting where possible. Real-time shadows only for player + key objects
  5. LOD System: Implement Level of Detail for all models (3 levels minimum)
  6. Update Loop: Use requestAnimationFrame. Skip updates for off-screen objects
  7. Physics: Limit physics bodies to visible area + small buffer

5.4 Environment Details

Lighting

  • Time of Day: Permanent sunset (golden hour) for initial release
  • Ambient Light: Warm orange (#ff9966) at intensity 0.6
  • Directional Light: Low angle, casting long shadows, simulating setting sun
  • Street Lamps: Point lights with warm glow, turn on as natural light fades
  • Neon Signs: Emissive materials with bloom post-processing
  • Building Windows: Random emissive rectangles, simulated interior lighting

Atmosphere

  • Fog: Exponential fog, density 0.015, color matches sunset sky
  • Particles: Floating dust motes (very subtle), occasional neon-colored confetti near venues
  • Skybox: Gradient dome from deep purple (top) to hot orange (horizon)
  • Reflections: Wet street surface with subtle reflections (normal map + roughness)

Street Props

  • Palm trees (instanced, 8-12 along the street)
  • Street lamps (instanced, every 20 meters)
  • Park benches (3-4 total)
  • Trash cans, newspaper stands, potted plants
  • Neon signs above venues (unique per venue)
  • Crosswalk markings, manhole covers, street cracks

  • Poly Count: 1,500 triangles maximum
  • Height: 1.7 units (meters) in world space

6.3 Camera System

Mode: Third-person follow camera (primary), with optional first-person toggle.

  • Default Distance: 6 meters behind player
  • Height Offset: 2 meters above player
  • Look Target: Player head height (1.6m)
  • Smoothing: Camera follows with 0.1s lag (smooth damping)
  • Collision: Camera raycasts to avoid clipping through buildings. If blocked, moves closer to player
  • FOV: 60 degrees (configurable in settings)

7 AI NPC System

7.1 Overview

The street feels alive through AI-controlled NPCs (Non-Player Characters). They walk around, enter/exit buildings, gather in groups, and can be interacted with by the player. Phase 1 targets 8-12 active NPCs at any time, with plans to scale to 30+ in multiplayer.

7.2 NPC Design

  • Style: Low-poly cartoonish, same aesthetic as player but distinct silhouettes
  • Variations: 6 unique base models (3 male, 3 female) with color/material variations
  • Poly Count: 1,200 triangles each (slightly simpler than player)
  • Animations: Idle, walk, talk, celebrate (4 animations minimum)

7.3 NPC Behaviors

NPCs use a simple state machine with the following states:

State Description Duration
IDLE Standing still, occasional idle animation 10-30s
WALKING Moving to a destination point Variable
TALKING In conversation with player or another NPC Until interaction ends
INTERACTING Using an object (bench, shop window, etc.) 15-45s
ENTERING_BUILDING Walking into a venue (disappears from street) 2-3s
EXITING_BUILDING Walking out of a venue (appears on street) 2-3s

7.5 NPC Interactions

When player approaches an NPC and presses E:

  1. NPC stops and faces player
  2. Dialog box appears with NPC name + greeting
  3. Player can select from 1-3 conversation options
  4. Options may include:
    • "What's happening around here?" (Lore/world building)
    • "How do I play [game]?" (Tutorial hints)
    • "See you around!" (End conversation)
  5. Some NPCs give quests or hints about secrets (Phase 2)

8.3 Asset Sharing

Optimization: The GameController maintains an asset cache. When a game requests an asset, it's loaded once and reused. Games should NOT load the same assets independently. Use AssetLoader.get('path/to/asset') which returns cached instances.

9 Game 1: Sky Ace (Flight Combat)

9.1 Game Overview

Sky Ace is an Ace Combat-inspired aerial combat game. Players pilot a stylized fighter jet through arcade-style missions, shooting down enemy aircraft and completing objectives. The game is accessible (simple controls) but rewards skill (advanced maneuvers, chain combos).

9.2 Game Flow

  1. Briefing Room: Player enters Sky Ace HQ venue interior. Briefing screen shows mission details
  2. Hangar: Player selects aircraft (1 available in Phase 1, 3+ in future)
  3. Launch: Aircraft takes off from runway, transitions to gameplay
  4. Gameplay: Aerial combat mission (2-5 minutes)
  5. Debrief: Score screen with stats, high score comparison, rewards
  6. Return: Player exits back to venue interior or street

9.3 Controls

Input Action
W / Up Arrow Pitch Down (dive)
S / Down Arrow Pitch Up (climb)
A / Left Arrow Roll Left + Turn Left
D / Right Arrow Roll Right + Turn Right
Space Fire Machine Guns
E / Shift Fire Missile (limited ammo, lock-on required)
Shift Boost (temporary speed increase, overheats)
C Change Camera (Cockpit / Chase / Cinematic)
Esc Pause Menu

9.4 Flight Mechanics

  • Physics: Arcade-style (not realistic flight sim). Momentum-based with generous turning
  • Speed Range: 200-800 km/h (scaled to game world)
  • Altitude: Minimum 50m (ground), maximum 3,000m (ceiling)
  • Stall: No stall mechanic (arcade accessibility)
  • Boost: 1.5x speed for 3 seconds, 5-second cooldown
  • Health: Aircraft has 100 HP. Collisions with ground = instant death

9.5 Mission Structure (Phase 1)

Mission 1: "First Flight" - Tutorial / Training

  • Objective: Destroy 5 training drones
  • Time Limit: 3 minutes
  • Enemies: Static drones (no AI, easy targets)
  • Rewards: Bronze/Silver/Gold medal based on time

Mission 2: "Neon Skies" - First Real Combat

  • Objective: Destroy 10 enemy fighters
  • Time Limit: 5 minutes
  • Enemies: Basic AI (follow player, shoot occasionally)
  • Environment: City at night with neon lights

Mission 3: "Ace in the Hole" - Boss Battle

  • Objective: Defeat Ace-class enemy squadron (3 elite enemies)
  • Time Limit: 5 minutes
  • Enemies: Advanced AI (evasive maneuvers, team tactics)
  • Environment: Coastal sunset

9.6 Scoring System

9.7 Visual Design

  • Aircraft Style: Stylized fighter jets, low-poly (3,000 triangles), cartoonish proportions
  • Environment: Floating islands, neon-lit city, clouds, ocean
  • Skybox: Dynamic sunset with gradient colors matching street aesthetic
  • Effects:
    • Engine trails (particle system)

  • HUD:
    • Speed indicator (analog gauge style)

    • Weapon status (machine gun heat, missile count)
    • Radar/minimap (top-down view of area)
    • Score + combo counter
    • Lock-on reticle (appears when missile can lock)

9.8 Audio Design

  • Engine: Continuous jet roar, pitch shifts with speed
  • Guns: Rapid-fire pew-pew (arcade style, not realistic)
  • Missiles: Launch whoosh, lock-on beep
  • Explosions: Satisfying boom with bass
  • Music: Synthwave/electronic, high energy, 120-140 BPM
  • Voice: Radio chatter (text-to-speech or recorded lines)

10.3 Modeling Guidelines

  • Software: Blender (primary), Maya/3ds Max acceptable
  • Export Format: GLB (binary GLTF) with embedded textures
  • Units: 1 unit = 1 meter in Blender
  • Origin: Model origin at base center for characters/buildings, at geometric center for props
  • Scale: Apply all transforms before export
  • UVs: Unwrap all models, minimize stretching, maximize texel density
  • Textures: Power-of-2 dimensions, baked lighting where possible

12 Multiplayer Roadmap

12.1 Phase 1: Single Player Foundation

Current Phase. All systems designed with multiplayer in mind but not implemented:

  • Player controller supports multiple input sources
  • EventBus system can broadcast local or network events
  • NPC system can be replaced with remote player data
  • Physics uses deterministic update steps

12.2 Phase 2: Social Features (No Real-Time Multiplayer)

  • Player profiles and avatars
  • Global leaderboards (async)
  • Friend system (async)
  • Leave messages for other players (like Dark Souls)
  • Ghost data: see other players' flight paths as translucent trails

12.3 Phase 3: Real-Time Multiplayer

Technology: WebRTC (P2P) for 2-4 players, WebSockets for matchmaking + >4 players

  • Co-op: 2 players in Sky Ace missions together
  • Versus: Dogfight mode, 2-4 players
  • Street: See other players walking around (instanced areas, max 20)
  • Sync Rate: 20Hz for positions, 10Hz for animations
  • Prediction: Client-side prediction with server reconciliation
  • Lag Compensation: 100ms buffer for hit detection

14.2 Production Build

The production build includes:

  • JavaScript minification + tree shaking
  • Texture compression (WebP/PNG optimization)
  • Asset lazy loading (games load on demand)
  • Service worker for offline support (Phase 2)
  • Source maps (for debugging, not deployed to prod)

14.3 Deployment Pipeline

Developer pushes to feature branch ↓ GitHub Actions runs tests + lint ↓ PR merged to develop ↓ Staging deployment (auto) ↓ QA tests on staging ↓ PR from develop → main ↓ Production deployment (manual trigger) ↓ Cloudflare Pages / Vercel / Netlify

Requirement Specification
